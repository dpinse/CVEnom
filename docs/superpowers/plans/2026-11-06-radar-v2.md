# Radar v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship radar v2: range-aware lanes with the KEV bug fixed, a global 24h/7d/14d/30d range, a Dashboard (summary line, flat/globe choropleth map with a country side panel, compact lanes, a severity volume chart), a Threats list page, a full threat page backed by a CVE timeline and affected versions, a drawer that never clips, and twelve new keyless feeds plus Exploit-DB and CIRCL OSINT.

**Architecture:**
- Backend first, then frontend, then e2e.
- One shared range module (`cvenom/ranges.py` and `frontend/src/lib/range.ts`) defines `24h | 7d | 14d | 30d`. Every range-aware endpoint takes `?range=` and validates it with the same `Literal`.
- Lane membership stays in two places that must agree: the SQL candidate query in `pipeline.lane_views` and the pure rule in `scoring.lanes_for_cve`. Both now take the range.
- A new `cve_event` table (migration **0008**, `down_revision = "0007"`) is the timeline. Collectors may emit explicit events. The pipeline also derives events from normalized CVEs and from story links, and inserts them idempotently.
- `cve.affected_versions` (also in 0008) is merged per source (OSV, NVD) in `db.upsert_cve`.
- New read endpoints sit on the existing read router, so they inherit `_utf8_query` → `rate_limit("read")` → `public_or_user`, in that order.
- Frontend: the range lives in the URL (`?range=`), falls back to localStorage, then to `7d`. TanStack Query keys include the range. The MapLibre map is reused and switched between `mercator` and `globe` with `setProjection`.

**Tech Stack:** Python 3.14, FastAPI, SQLAlchemy 2, Alembic, Postgres 16, Redis, Celery, feedparser, httpx (respx in tests). Vite + React 19 + TypeScript strict, TanStack Query, react-router 7, MapLibre 6 + world-atlas, Vitest + MSW, Playwright (chromium + firefox). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-radar-v2-design.md`. The layout, copy and behaviour reference is `docs/superpowers/design/cvenom-radar-v2-mockup.html` (open it in a browser; skip its `const WORLD = …` line when reading).

House rules carried from earlier plans:
- **Backend tests** run from `backend/` as `python -m pytest -q …`. They need the test Postgres (`CVENOM_TEST_PG_PORT`, see `backend/tests/conftest.py`) and Redis on `localhost:6379`. Every `pytest` command below assumes both.
- **Frontend checks** run from `frontend/`: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`, `npm run e2e`, `npm run format:check`.
- **Green at every task.** pytest, vitest, lint, typecheck and build pass at the end of every task. A frontend task that changes behaviour an existing Playwright spec asserts updates that assertion in the same task. Task 18 adds the new e2e coverage.
- Commit locally only. Never `git push`, `fetch` or `pull`, never touch `main`, never open PRs, never stage `.superpowers/`. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Router order:** every new `/api` route goes on `routes_read.router`, so `rate_limit` runs before auth (`test_every_api_route_rate_limits_before_auth`).
- **`restricted_sources(user)`:** individual records from `ransomware.live` / `ransomware_live` are filtered in SQL, before `LIMIT` and in any `count`, for anonymous callers. This applies to new story lists, the `events` list (a `first_news` row whose `source` is restricted) and country `events`. Aggregate counts stay public.
- **Response cache:** a new cached path is added to `CACHE_PATHS` with exactly its allowed query params. Free-text params are never allowed (they bypass the cache).
- **Sanitise at ingest:** every stored text field goes through `sanitize_text`, and every JSON-column string goes through `_sanitize_details`. Raw URL columns are stored exactly as `validate_http_url` accepted them.
- **Frontend XSS contract:** no `dangerouslySetInnerHTML`. API text renders only through `<Text>` / `decodeEntities` (decode once). Every link goes through `safeHref` / `<ExternalLink>`.
- **Remote URLs in source:** `frontend/src/test/project.test.ts` allow-lists them. This plan adds none to `frontend/src`. The CWE generator script lives outside `frontend/src`.
- **Initial bundle** stays ≤ 250 KB gzip with no MapLibre (`project.test.ts`). The threat page and the CWE map load lazily.
- **Settings have no env prefix.** Every `Settings` field has a `# NAME=` line in `.env.example` (`test_env_example_covers_settings`).
- **DB-IP attribution** (`GeoAttribution`) stays visible wherever geo data renders (map legend and side panel).
- Times shown in the UI are UTC. "Within R" for a `date` column means `>= utc_today - RANGE_DAYS[R]`.

## Review Focus

- **Old links keep working.** `/history?kev=true&q=ivanti&page=2`, `/history?tab=stories`, `/search?q=x` and a bookmarked `/?cve=CVE-…` must land on the right view, not on NotFound or an empty filter. Test in Task 10: the `legacyThreatsSearch` table plus a routes test for each redirect.
- **An exact CVE id search ignores the range.** Typing `CVE-2026-109619` into Threats while the range is 24h must find that CVE even though its KEV listing is 9 days old, because people paste ids from advisories. Test in Task 7: `/api/cves?range=24h&q=CVE-2026-109619` returns it with `total == 1`.
- **Shrinking the range under a deep page.** On `/threats?page=4&range=30d`, switching to 24h must show "No results on this page" with the real total and a first-page link, not an error and not a stuck spinner. Test in Task 14.
- **Countries the 110m atlas cannot draw.** Singapore or Malta with the most events must still top the side list and be selectable by keyboard. One country alone gets bucket 4. `max = 0` or a NaN `events` value must not throw or paint. Tests in Task 11 (`choroplethBucket` table, `CountryList` with `SG`).
- **Storage blocked and junk params.** In a private window, with `localStorage` throwing, plus `?range=90d`, the app must render at `7d`, never crash, and rewrite the URL to a valid range on the first change. The same goes for `cvenom.mapMode`. Tests in Task 10 (`useRange`) and Task 11 (`useMapMode`).

**Interfaces:**
- Produces in `cvenom/ranges.py`:
  - `RangeKey = Literal["24h", "7d", "14d", "30d"]`
  - `DEFAULT_RANGE: RangeKey = "7d"`
  - `RANGE_DAYS: dict[str, int] = {"24h": 1, "7d": 7, "14d": 14, "30d": 30}`
  - `range_start(now: datetime, rng: RangeKey) -> datetime`: UTC `now - RANGE_DAYS[rng]` days.
  - `range_start_date(now: datetime, rng: RangeKey) -> date`: UTC `now.date() - RANGE_DAYS[rng]` days.
- Produces `lanes_for_cve(v: CveView, now: datetime, cfg: Settings, rng: RangeKey = DEFAULT_RANGE) -> set[Lane]`:
  - **EXPLOITED** iff `v.kev and v.kev_added is not None and v.kev_added >= range_start_date(now, rng)`.
  - **LIKELY** iff `not v.kev and epss_percentile >= cfg.epss_percentile_threshold and published within cfg.likely_window_days`. This is unchanged and independent of the range.
  - **LOUD** iff `v.recent_story_count >= 1`. The caller counts stories published at or after `range_start(now, rng)`.
  - **FRESH** iff `not v.kev and cvss >= cfg.fresh_cvss_floor and published >= range_start(now, rng)`.
- Produces `lane_views(session, now, rng: RangeKey = DEFAULT_RANGE) -> dict[Lane, list[CveView]]`:
  - The SQL candidates mirror the rules above: `Cve.kev.is_not(True)` on LIKELY and FRESH, and the story cutoff is `range_start`.
  - The sort is unchanged: EXPLOITED newest `kev_added` first, the rest by `heat_rank`.
- Produces `loud_stories(session, now, *, limit, rng: RangeKey = DEFAULT_RANGE, exclude_sources)`.
- Produces `_recent_counts(session, ids, since: datetime)`.
- Produces `GET /api/lanes?range=7d&limit=5`:

  - `limit` is `Query(ge=1, le=100)`, default `5`. `total` is the full lane count before `limit`.
  - An invalid `range` gives 422.
  - `LANE_CAP` is removed.
- Produces `GET /api/stories/loud?range=&limit=`.
- Produces `CACHE_PATHS["/api/lanes"] = {"range", "limit"}` and `CACHE_PATHS["/api/stories/loud"] = {"limit", "range"}`.
- Remove `Settings.exploited_window_days` and its `.env.example` line (now unused). `loud_window_hours` and `fresh_window_hours` stay: `heat_rank` and `_recent_counts` callers without a range still read them.
